# 切帧连续性优化（2026-11-01）

原实现切帧时立即移除图片、显示遮罩，并在请求清理时撤销仍在显示的 Blob URL；每次还固定等待70毫秒，且图片地址中的 request_id 使浏览器无法复用相同帧的缓存。

现在将一组图片、标签和遥测作为完整快照提交。切帧期间保留上一组画面，新组全部完成浏览器解码后一次替换，图片角标跟随实际显示帧。元数据仍逐次请求，避免缓存旧标签；只有请求帧、来源、证据窗口和刷新版本全部匹配时才允许编辑。快速连续操作会取消过期请求，失败保留上一组画面并锁定标签写入。

图片改用稳定 HTTP 地址，复用已解码图片；前端 LRU 按解码像素估算限制为64 MiB、最多128张（浏览器自身缓存和页面正在显示的图片由浏览器管理）。移除固定70毫秒等待，使用渲染帧合并连续输入。播放根据 FPS、倍速和墙钟时间调度，移除固定80毫秒的额外间隔。冷解码速度仍取决于视频、磁盘和机器性能。

旧快照只在相同数据集、episode、模式、历史配置和行为参考跨度下保留。不同证据窗口不复用旧快照；切回状态模式立即隐藏未来参考及其放大图。首次加载和真实缺失仍显示占位卡。

未改后端 API、数据集格式、导出协议和训练适配器。

## 验证

- `cd frontend && npm run build`。
- `./scripts/test.sh -q`：41项通过。
- 浏览器回归：人为延迟单路相机、取消旧元数据/图片请求、快速跳帧、热缓存重访、重新读取标签及检查写入帧、图片加载失败、模式及放大图切换、键盘与游标、episode与数据集切换、缺失历史、单时刻历史、播放暂停。
- 在连续切帧的逐渲染帧采样中，检查无空白、无三相机混帧、无加载遮罩。
- 真实640×480三路AV1样例：从源帧150开始，连续切至151/152/153分别约136/117/134毫秒，回到已访问的150约33毫秒；播放3秒后停在240。共217次渲染采样，无空白或混帧，无页面异常。耗时包含浏览器自动化操作，仅为本机单次实测，不代表所有视频或机器的性能。

结果记录在 [frame-switching-validation.json](frame-switching-validation.json)。
