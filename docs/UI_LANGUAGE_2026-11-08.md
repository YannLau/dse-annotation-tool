# 软件界面中英文切换 · 2026-11-08

[English](UI_LANGUAGE_2026-11-08_EN.md) | 简体中文

## 切换与记忆

右上角“界面语言”下拉框提供“简体中文”和“English”，初始默认中文。选择后立即更新工作台、字段与规则、行为与校准、导出页面、导出检查器、页面内文件夹浏览器和悬浮时间轴的界面文字；系统文件夹选择窗口的标题也使用打开时所选的语言。

语言选择保存在当前浏览器、当前站点的本地存储中，刷新后恢复。同一站点的其他已打开页面也会同步语言。清除站点数据会重置选择。界面语言不属于项目 schema 或训练配置，不写入导出数据集。

切换时保留当前页面、源帧、选区、模式、放大画面与未确认的整组草稿。切换不需要重新导入或重新审核标签。刷新前仍应让正常的项目自动保存完成；语言偏好本身在选择时立即保存。

已经显示的系统错误、审核跳过原因和本帧完成检查结果会随语言重新显示，不需要重新执行检查。检查器中的原始 Parquet/JSON、用户输入的任务文本、路径、人工备注和稳定字段/类别 key 保持原内容。

## 自定义字段与类别的英文文字

“字段与规则”新增以下可选配置：

| 对象 | 属性 | 英文界面的使用方式 |
|---|---|---|
| 字段 | `label_en` | 优先显示英文名称，未填则保留原显示名或 field_id |
| 字段 | `description_en` | 优先作为英文说明，未填则翻译已知的默认说明或保留自定义原文 |
| 类别 | `label_en` | 优先显示英文名称；未填时，保持默认中文名称的内置类别使用内置英文翻译，自定义类别回退到稳定 key |

中文类别文字仍保存在 `label_zh` 中。这些英文属性与原有显示文字一样，属于 schema 配置；填写后需校验并发布才会进入当前活动版本和后续导出。发布仍采用原有版本迁移规则，旧标签需要复核。仅切换界面语言不会发布 schema，也不会修改类别 ID、标注值、审核状态或 loss mask。

完整字段含义见[数据集说明书](ANNOTATED_DATASET_MANUAL_ZH.md#6-schemajson标签字典与规则)。

## 更新现有安装

```bash
npm run build --prefix frontend
```

然后重启服务，继续使用原来的 `--work` 目录并刷新浏览器。已在本机完成构建的安装只需重启服务和刷新页面。

## 验证与复现

翻译和动态消息检查：

```bash
npm run test:i18n --prefix frontend
./scripts/test.sh -q
```

`test:i18n` 检查全部 686 条翻译、插值参数、组合错误、中文路径原样保留，以及默认/自定义类别的显示回退。Python 回归同时验证原生文件夹窗口的英文标题、默认中文、语言参数校验和选中路径不变。

浏览器验收在独立临时工作库和明确的合成数据上进行：

```bash
./scripts/run.sh --work /tmp/dse-i18n-test --port 8891
# 另一个终端；需要 Playwright，或用 DSE_PLAYWRIGHT_MODULE 指定其模块文件
node scripts/validate_i18n.mjs
```

可用 `DSE_BASE_URL` 设置服务地址，`DSE_BROWSER_EXECUTABLE` 指定 Chrome。脚本拒绝操作 `/tmp/dse-i18n-*` 以外的工作库，并打印合成夹具、截图和机器报告所在的临时目录。

验收覆盖全部主要页面、已有提示重新翻译、文件夹浏览与系统选择器回退、刷新后语言/草稿恢复、切换时保留帧和选区、检查器页签与帧保留，以及窄窗口下语言控件可见。对比标注/选区/审核/事件/schema 表和源数据、独立导出的内容指纹，核对语言切换的数据完整性。

本次实测：52 项 Python 回归、686 条翻译校验、TypeScript/Vite 生产构建和浏览器验收全部通过，无页面运行错误；源数据与独立导出的内容指纹保持一致。结果见[机器验收记录](ui-language-validation.json)。
